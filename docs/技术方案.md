# 本地音乐播放器技术方案（Android）

状态：已确认，工程已创建于 MusicPlayer 目录  
范围：v1 可交付；v2 仅做接口预留，不实现

---

## 1. 背景与目标

在 Android 手机上播放用户本地目录中的音频文件。文件来自下载、蓝牙传输等，不经过云端，不上传到服务器。

v1 目标：用户选一个目录 → 列出 mp3/wav → 点击即播 → 回桌面继续播 → 下次打开恢复目录、歌曲和进度（不自动播放）。

---

## 2. 产品范围

### 2.1 v1 要做

| 编号 | 需求 | 说明 |
|---|---|---|
| F1 | 选择目录 | 用户选择手机上的一个文件夹，扫描其中音频 |
| F2 | 格式 | 同时支持 `.mp3`、`.wav`（大小写不敏感） |
| F3 | 排序 | 文件列表按文件名升序（使用当前系统 locale） |
| F4 | 列表 UI | 上半部分：目录名 + 右侧「更换目录」；下方大字号文件名列表 |
| F5 | 控制 UI | 下半部分：进度条、上一首、播放/暂停、下一首 |
| F6 | 点选播放 | 点击列表项立即播放该文件，从 0 开始 |
| F7 | 播完行为 | 自动播放下一首；已是最后一首则停止，不循环 |
| F8 | 启动恢复 | 打开 App 自动加载上次目录、上次文件、上次进度；不自动播放 |
| F9 | 进度持久化 | 播放中、切歌、回后台、退出时保存进度 |
| F10 | 后台播放 | 回到桌面后继续播放（系统通知栏会有播放通知） |

### 2.2 v1 明确不做

- 音量条（使用系统音量键）
- 循环、随机、单曲循环
- 歌词、封面、搜索、多歌单、收藏
- 从其它 App（文件管理器）打开音频（见 v2）
- iOS / 微信小程序 / 网页版

### 2.3 v2（后续，本文只约定接入方式）

从系统文件管理器等第三方 App 点击音频文件时，可选择本 App 打开：

1. 立即播放该文件
2. 尽量扫描该文件所在目录的全部 mp3/wav，按文件名排序作为当前列表
3. 若系统只授予单文件权限、无法列出同目录其它文件：只播放这一首，并提示用户用「更换目录」选择该文件夹

v1 **不注册** `ACTION_VIEW`，避免现在打开只能播一首、体验不完整。播放器与列表的数据模型按「当前目录 + 当前文件」设计，v2 只增加入口，不改核心结构。

## 3. 为什么必须是 Android App

微信小程序无法选择并持久访问手机任意目录，也无法可靠地「下次打开还读同一个文件夹」。网页/PWA 在 Android 上的目录选择和后台播放同样受限。

因此只做 Android 原生应用。

---

## 4. 技术选型

| 项 | 选择 | 原因 |
|---|---|---|
| 语言 | Kotlin | Android 官方主语言 |
| UI | Jetpack Compose | 列表 + 底部控制栏布局简单，适合本需求 |
| 最低版本 | minSdk 26（Android 8.0） | 前台服务、通知渠道稳定；覆盖目前在用的安卓机 |
| 目标版本 | targetSdk 35 | 跟当前 Android Gradle Plugin 默认对齐，创建项目时按 AS 模板微调 |
| 播放器 | Media3 ExoPlayer | 官方播放库，mp3/wav 原生支持，和 MediaSession 一体 |
| 后台播放 | Media3 `MediaSessionService` | 系统媒体通知、耳机键、回桌面续播的标准做法 |
| 选目录 | Storage Access Framework（`OpenDocumentTree`） | Android 10+ 不能静默扫全盘，这是官方允许的「用户授权一个文件夹」方式 |
| 偏好存储 | DataStore Preferences | 存目录 URI、上次文件、进度；替代 SharedPreferences |
| 架构 | 单 Activity + ViewModel + Repository | 体量小，不引入多模块 |

不引入：Room（无复杂库表）、Hilt（单 Activity 用手动注入或默认 ViewModel 工厂即可）、网络库。

## 5. 整体架构

```
┌─────────────────────────────────────────────┐
│                 UI (Compose)                │
│  PlayerScreen  ←  PlayerViewModel           │
└──────────────────────┬──────────────────────┘
                       │
         ┌─────────────┴─────────────┐
         ▼                           ▼
┌─────────────────┐         ┌─────────────────┐
│ LibraryRepository│         │  PlaybackStore  │
│ 扫描目录 / 列表  │         │  DataStore 持久化│
└─────────────────┘         └─────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────┐
│     PlaybackService (MediaSessionService)   │
│     ExoPlayer + MediaSession + 通知栏       │
└─────────────────────────────────────────────┘
```

职责划分：

- **PlayerScreen**：只负责展示和点击事件
- **PlayerViewModel**：把「列表、当前曲、播放/暂停、进度」变成 UI 状态；转发用户操作
- **LibraryRepository**：拿着已授权的目录 URI，列出 mp3/wav 并排序
- **PlaybackStore**：读写上次目录、文件、进度、是否曾选过目录
- **PlaybackService**：真正播音频、发通知、在 App 回桌面后继续活着

Activity 只做两件事：申请通知权限（Android 13+）、把界面和 Service 连上。

## 7. 数据模型

```kotlin
data class AudioFile(
    val documentUri: Uri,     // 用于播放，不依赖绝对路径

    val positionMs: Long,

```

列表只显示 `displayName`，不显示歌手、专辑、时长。

## 8. 目录选择与扫描

### 8.1 为什么用 SAF，不用路径扫描

Android 10 起 ent 分区存储。没有 `MANAGE_EXTERNAL_STORAGE`（Play 政策严格，且本需求不需要）就不能按 `/storage/emulated/0/Download/...` 列目录。

正确做法：

1. 用户点「选择目录 / 更换目录」
2. 启动 `ActivityResultContracts.OpenDocumentTree()`
3. 对返回的 `treeUri` 调用  
   `contentResolver.takePersistableUriPermission(uri, FLAG_GRANT_READ_URI_PERMISSION)`
4. 把 `treeUri` 写入 DataStore
5. 用 `DocumentFile.fromTreeUri()` 列出直接子文件（v1 不递归子文件夹，避免下载目录里套很多层、列表不可控）

若产品确认需要包含子文件夹，作为变更项再改；默认 **只扫所选目录这一层**。

### 8.2 文件过滤

满足任一即可入列表：

- 扩展名为 `.mp3` 或 `.wav`（忽略大小写）
- 或 MIME 为 `audio/mpeg`、`audio/wav`、`audio/x-wav`、`audio/wave`

隐藏文件（以 `.` 开头）忽略。

### 8.3 排序

`displayName` 使用 `String.CASE_INSENSITIVE_ORDER` 再套系统默认 Collator（`Collator.getInstance()`），保证中文、数字文件名符合用户语言习惯。

### 8.4 目录名展示

优先 `DocumentFile.fromTreeUri(treeUri).name`。取不到时展示「已选择的目录」，不展示一长串 `content://`。

### 8.5 权限失效

下次打开时若 `takePersistableUriPermission` 已失效、目录被删、或扫不到任何音频：

- 列表为空
- `needsDirectory = true`
- 文案提示重新选择目录
- 不崩溃、不自动弹系统目录选择器（避免一打开就打断用户）

## 9. 播放引擎与后台

### 9.1 组件

- `ExoPlayer` 在 `PlaybackService` 中创建，进程内单例
- `MediaSession` 对接系统通知、蓝牙/耳机按键（系统会提供播放/暂停/上一首/下一首，与 App 内按钮同一套命令）
- Service 类型：`foregroundServiceType="mediaPlayback"`
- 通知渠道：播放中常驻，停止播放后可移除前台状态（进程可被回收，下次打开再恢复进度）

### 9.2 播放列表如何交给播放器

ViewModel 扫描得到 `List<AudioFile>` 后，转成 `MediaItem` 列表交给 ExoPlayer：

- `MediaItem.Builder().setUri(documentUri).setMediaId(uriString).setMediaMetadata(title = displayName)`
- 使用 `REPEAT_MODE_OFF`
- **不开启** shuffle
- 当前曲播完：ExoPlayer 默认播下一首；最后一首结束时 `STATE_ENDED`，UI 显示暂停、进度停在结尾

### 9.3 点击列表

- 调用 `player.seekTo(index, 0)` 然后 `play()`
- 即：从该文件开头播放，不是恢复该文件上次进度  
  （「上次进度」只用于 App 冷启动恢复，不用于点击另一首歌）

### 9.4 上一首 / 下一首

- 下一首：当前不是最后一首则 `seekToNext()` 并从 0 播放；已是最后一首则忽略（或保持当前，不循环到第一首）
- 上一首：当前不是第一首则 `seekToPrevious()` 并从 0 播放；已是第一首则忽略
- 进度条拖到任意位置只改变当前曲位置，不切歌

补充约定（建议默认，确认时可改）：上一首在当前曲已播放超过 3 秒时，先回到本曲开头，再按一次才到上一首。这是常见播放器行为。若希望「按一下必到上一首」，创建项目前说明即可。

### 9.5 进度条

- UI 约每 200–500ms 读 `player.currentPosition`
- 用户拖动时暂停进度上报，松手后 `seekTo(position)`
- duration 未知（0 或 `C.TIME_UNSET`）时进度条不可拖、显示 `--:--`

### 9.6 后台续播

用户按 Home：Activity 销毁或进入后台，`PlaybackService` 保持前台，ExoPlayer 继续播。

这是 Android 8+ 硬性要求：后台播音频必须有一条可见通知。通知内容：当前文件名、播放/暂停、上一首、下一首。不做音量条，通知里也不放音量。

Android 13+ 启动时请求 `POST_NOTIFICATIONS`。用户拒绝通知权限时：仍尝试播放，但系统可能限制前台服务；界面提示「为了回桌面继续播放，需要通知权限」。

## 10. 状态持久化

### 10.1 存储内容（DataStore）

| 键 | 含义 |
|---|---|
| `tree_uri` | 已授权目录 |
| `file_uri` | 上次播放文件 |
| `position_ms` | 上次进度 |

不存播放/暂停状态。启动一律为暂停。

### 10.2 何时写入

| 时机 | 写入内容 |
|---|---|
| 选中新目录并扫描成功 | `tree_uri`，清空或重设当前文件 |
| 开始播某一首 | `file_uri`，`position_ms = 0` |
| 播放中 | `position_ms` 节流写入，约每 2 秒一次 |
| 用户 seek | 立即写 `position_ms` |
| 切歌 | `file_uri` + `position_ms = 0` |
| `onPause` / `onStop` | 立即写当前进度 |
| Service `onDestroy` / 播放结束 | 立即写当前进度 |

最后一首自然结束：保存该文件 URI，进度为时长（或 0，见下条）。

建议：自然播放结束停在最后一首结尾时，保存 `position_ms = duration`；下次打开仍停在这首、进度条在结尾、不自动播。用户点播放则从开头重播（因为已在结尾）。也可改为结束后进度归 0。默认采用 **停在结尾**。

### 10.3 冷启动顺序

1. 读 DataStore
2. 若无 `tree_uri` → 空态，等待用户选目录
3. 若有 → 恢复 persistable 权限，扫描列表
4. 在列表中按 `file_uri` 匹配；匹配到则 `seekTo(index, positionMs)`，**不调用 play()**
5. 匹配不到（文件被删）→ 停在列表第一首、进度 0、不播放；若列表为空则空态

## 11. 界面结构

单屏，竖屏优先。不强制横屏。

```
┌─────────────────────────────────┐
│  目录名              [更换目录]  │  ← 未选目录时按钮文案为「选择目录」
├─────────────────────────────────┤
│                                 │
│  文件名 a.mp3                   │  ← 大字号，约 20sp
│  文件名 b.wav          (当前)   │  ← 当前曲高亮，不靠封面/图标
│  文件名 c.mp3                   │
│  ...                            │
│                                 │
├─────────────────────────────────┤
│  0:12 ────────●──────── 3:45    │  ← 进度条 + 已播/总时长
│                                 │
│       上一首   播放/暂停   下一首 │
└─────────────────────────────────┘
```

交互：

- 列表可滚动，底部控制区固定
- 当前播放项尽量滚进可视区（启动恢复和切歌时）
- 空目录：列表区域提示「该目录没有 mp3 或 wav 文件」
- 未选目录：提示「请选择包含音频的文件夹」
- 无独立设置页、无启动闪屏

颜色与字体：系统默认浅色/深色跟随系统即可，v1 不做自定义主题皮肤。

## 12. 权限清单

| 权限 | 用途 | 时机 |
|---|---|---|
| 无 `READ_EXTERNAL_STORAGE` | 用 SAF 授权的目录，不申请读全盘 | — |
| 无 `WRITE` | 只读播放 | — |
| `FOREGROUND_SERVICE` | 后台播放服务 | 安装即可 |
| `FOREGROUND_SERVICE_MEDIA_PLAYBACK` | Android 14 前台服务类型 | 安装即可 |
| `POST_NOTIFICATIONS` | Android 13+ 播放通知 | 首次需要后台播放前请求 |
| persistable URI permission | 记住用户选的目录 | 用户选目录之后 |

`AndroidManifest` 中 Service 声明 `foregroundServiceType="mediaPlayback"`。v1 不声明 `VIEW` intent-filter。

## 13. v2 预留（不实现）

为避免以后大改，v1 遵守：

1. 列表来源是「当前 `List<AudioFile>`」，不写死「只能来自 OpenDocumentTree」
2. 增加 `LibraryRepository.loadFromTree(uri)`；预留 `loadFromOpenedFile(fileUri)` 空接口或 TODO，v2 再实现
3. v2 实现要点（记录在此，创建项目时不写死代码）：
   - Manifest 增加 `ACTION_VIEW`，`mimeType` 含 `audio/mpeg`、`audio/wav`、`audio/*`
   - 收到 URI 后先 `play(uri)`
   - 优先用 MediaStore 的 `RELATIVE_PATH` / `BUCKET_ID` 查同目录音频
   - 查不到则单文件列表 + 提示选目录
   - 单文件 `content://` 通常没有父目录列文件权限，不能假设 `File(parent).listFiles()` 可用

## 14. 播放状态机（v1）

```
未选目录 ──选择目录──► 已加载列表（暂停）
                              │
                    点击列表项 / 点播放
                              ▼
                         播放中
                          │  │
              点暂停 / 回桌面仍保持播放
                          │
                     暂停 ◄─┘
                          │
              最后一首结束 ──► 停止（STATE_ENDED，停在结尾）
```

回桌面 **不是** 状态变化：仍是「播放中」，只是 Activity 不可见。

## 15. 关键流程

### 15.1 首次使用

1. 打开 App → 空态 + 「选择目录」
2. 系统文件夹选择器
3. 持久化读权限 + 扫描 + 按文件名排序
4. 若有文件：当前曲为第一首、进度 0、暂停
5. 用户点击某项或点播放后才出声

### 15.2 再次打开

1. 读 DataStore → 扫目录 → 定位上次文件和进度 → 暂停等待

### 15.3 更换目录

1. 新 treeUri 替换旧权限（可释放旧 persistable permission）
2. 新列表替换；当前曲重置为第一首、进度 0、暂停（不自动播放）

## 16. 异常与边界

| 情况 | 处理 |
|---|---|
| 文件在播放中被删除 | 停止当前曲，尝试下一首；列表下次扫描刷新 |
| 损坏/不支持的编码 | 提示「无法播放该文件」，自动跳下一首；已是最后一首则停止 |
| 0 字节文件 | 不进入列表，或进入后播放失败按上一条 |
| 同名文件 | URI 不同则都显示，文件名可以重复 |
| 目录内文件数千个 | v1 一次性列出（DocumentFile 在主线程外 IO）；若明显卡顿再改为分页，首版不做 |
| 耳机断开 | 跟随 ExoPlayer/系统默认：暂停 |
| 来电 | 系统音频焦点：暂停或降低音量，挂断后不自动恢复播放（避免突然出声）。默认 **不自动恢复** |
| 多窗口/旋转 | 配置变化由 Compose 保留 ViewModel，播放在 Service 中，不中断 |

## 17. 测试要点（实现后按此验收）

1. 选含 mp3、wav、其它类型的文件夹：列表只有音频，且按文件名排序
2. 点击第三首立即播放；上一首/下一首顺序正确；最后一首播完停止
3. 播放中按 Home，声音不停，通知栏可暂停/继续
4. 杀进程后重开：目录、歌曲、进度恢复，处于暂停
5. 更换目录后列表更新，不再读旧目录
6. 撤销目录权限或删除文件夹后重开：提示重新选择，不崩溃
7. 不展示音量条；音量键可调声
8. 通知权限拒绝后，前台播放仍尽量可用，并有提示
