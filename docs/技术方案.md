# 本地音乐播放器技术方案（Android）

状态：v1 已按本文落地；后续见第 19 节

范围：v1 可交付；v2 只记录接入约定，不实现、不预留空接口

---

## 1. 背景与目标

在 Android 手机上播放用户本地目录中的音频文件。文件来自下载、蓝牙传输等，不经过云端，不上传到服务器。

v1 目标：用户选一个目录 → 列出 mp3/wav → 点击即播 → 回桌面继续播 → 进程被杀后再次打开恢复目录、歌曲和进度（不自动播放）。若播放服务仍存活，重新进入界面时展示真实播放状态，不打断正在播放的内容。

---

## 2. 产品范围

### 2.1 v1 要做

| 编号 | 需求 | 说明 |
|---|---|---|
| F1 | 选择目录 | 用户选择手机上的一个文件夹，扫描其中音频 |
| F2 | 格式 | 只支持扩展名为 `.mp3`、`.wav` 的文件（大小写不敏感） |
| F3 | 排序 | 按文件名用系统 locale 的 Collator 升序；同名再用 URI 稳定排序。不做自然数字排序 |
| F4 | 列表 UI | 上半部分：目录名 + 右侧「更换目录」；下方大字号文件名列表 |
| F5 | 控制 UI | 下半部分：进度条、上一首、播放/暂停、下一首 |
| F6 | 点选播放 | 点击列表项立即播放该文件，从 0 开始 |
| F7 | 播完行为 | 自动播放下一首；已是最后一首则停止，不循环。停在结尾后再按播放：从该曲开头重播 |
| F8 | 启动恢复 | 见第 10.3 节：Service 仍存活则跟 Service；否则从 DataStore 恢复并保持暂停 |
| F9 | 进度持久化 | 由 Service 保存当前文件和进度；正常操作立即写，异常杀进程最多丢失约 2 秒 |
| F10 | 后台播放 | 回到桌面后继续播放（系统媒体通知由 Media3 提供） |

### 2.2 v1 明确不做

- 音量条（使用系统音量键）
- 循环、随机、单曲循环
- 歌词、封面、搜索、多歌单、收藏
- 刷新按钮；回到前台时不自动重扫目录
- 从其它 App（文件管理器）打开音频（见 v2）
- iOS / 微信小程序 / 网页版

### 2.3 v2（后续，本文只约定接入方式）

从系统文件管理器等第三方 App 点击音频文件时，可选择本 App 打开：

1. 立即播放该文件
2. 尽量扫描该文件所在目录的全部 mp3/wav，按文件名排序作为当前列表
3. 若系统只授予单文件权限、无法列出同目录其它文件：只播放这一首，并提示用户用「更换目录」选择该文件夹

v1 **不注册** `ACTION_VIEW`。不为此预留空方法或 TODO。v1 已用 URI 而非绝对路径表示文件和目录，v2 增加入口时再实现扫描逻辑。

## 3. 为什么必须是 Android App

微信小程序无法选择并持久访问手机任意目录，也无法可靠地「下次打开还读同一个文件夹」。网页/PWA 在 Android 上的目录选择和后台播放同样受限。

因此只做 Android 原生应用。

---

## 4. 技术选型

| 项 | 选择 | 原因 |
|---|---|---|
| 语言 | Kotlin | Android 官方主语言 |
| UI | Jetpack Compose | 列表 + 底部控制栏布局简单，适合本需求 |
| 最低版本 | minSdk 26（Android 8.0） | 前台服务稳定；覆盖目前在用的安卓机 |
| 目标版本 | targetSdk 35 | 跟当前 Android Gradle Plugin 默认对齐 |
| 播放器 | Media3 ExoPlayer | 官方播放库，mp3/wav 原生支持，和 MediaSession 一体 |
| 后台播放 | Media3 `MediaSessionService` | 系统媒体通知、耳机键、回桌面续播的标准做法 |
| 选目录 | Storage Access Framework（`OpenDocumentTree`） | Android 10+ 不能静默扫全盘，这是官方允许的「用户授权一个文件夹」方式 |
| 偏好存储 | DataStore Preferences | 存目录 URI、上次文件、进度 |
| 架构 | 单 Activity + ViewModel + Repository | 体量小，不引入多模块 |

不引入：Room、Hilt、网络库。

播放器、播放队列、当前曲和播放位置的**唯一事实来源**是 `PlaybackService` 中的 ExoPlayer。Activity / ViewModel 通过 `MediaController` 观察和控制它，不在 UI 层另维护一份会覆盖 Service 的播放状态。

## 5. 整体架构

```
┌─────────────────────────────────────────────┐
│                 UI (Compose)                │
│  PlayerScreen  ←  PlayerViewModel           │
└──────────────────────┬──────────────────────┘
                       │
         ┌─────────────┴─────────────┐
         ▼                           ▼
┌─────────────────┐         ┌─────────────────┐
│ LibraryRepository│         │  PlaybackStore  │
│ 扫描目录 / 列表  │         │  DataStore 持久化│
└─────────────────┘         └─────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────┐
│     PlaybackService (MediaSessionService)   │
│     ExoPlayer + MediaSession                │
│     （媒体通知由 Media3 自动管理）            │
└─────────────────────────────────────────────┘
```

职责划分：

- **PlayerScreen**：只负责展示和点击事件
- **PlayerViewModel**：把曲库状态和 `MediaController` 观察到的播放状态变成 UI 状态；转发用户操作。不在连接已有队列的 Service 时强制 `pause()` 或重设 playlist
- **LibraryRepository**：拿着已授权的目录 URI，列出 mp3/wav 并排序
- **PlaybackStore**：
  - ViewModel 只写 `tree_uri`（选目录成功后）
  - Service 只写 `file_uri`、`position_ms`
- **PlaybackService**：真正播音频；在 App 回桌面后继续活着。Service 内创建**一个** ExoPlayer 实例，不是进程级全局 Singleton

Activity 负责把界面和 Service 连上。v1 **不申请** `POST_NOTIFICATIONS`。

## 7. 数据模型

```kotlin
data class AudioFile(
    val documentUri: Uri,     // 用于播放，不依赖绝对路径
    val displayName: String,  // 列表展示用文件名（含扩展名）
    val mimeType: String?     // 仅展示/调试，不作为是否入列的依据
)

sealed interface LibraryState {
    data object NoDirectory : LibraryState
    data object Loading : LibraryState
    data class Loaded(
        val directoryName: String,
        val tracks: List<AudioFile>
    ) : LibraryState
    data object PermissionLost : LibraryState
    data class Error(val message: String) : LibraryState
}

data class PlayerUiState(
    val library: LibraryState,
    val currentIndex: Int,            // -1 表示没有当前曲
    val isPlaying: Boolean,
    val positionMs: Long,
    val durationMs: Long,
    val durationKnown: Boolean,
    val errorMessage: String?         // 播放失败等瞬时提示，与曲库错误分开
)

data class PersistedPlayback(
    val treeUri: String,              // 目录树 URI
    val fileUri: String,              // 上次文件 URI
    val positionMs: Long
)
```

列表只显示 `displayName`，不显示歌手、专辑、时长。

`Loaded` 的 `tracks` 可以为空：表示目录授权仍有效，只是当前没有 mp3/wav。不得把空目录表示成 `NoDirectory` 或 `PermissionLost`。

## 8. 目录选择与扫描

### 8.1 为什么用 SAF，不用路径扫描

Android 10 起引入分区存储。没有 `MANAGE_EXTERNAL_STORAGE`（Play 政策严格，且本需求不需要）就不能按 `/storage/emulated/0/Download/...` 列目录。

正确做法：

1. 用户点「选择目录 / 更换目录」
2. 启动 `ActivityResultContracts.OpenDocumentTree()`
3. 对返回的 `treeUri` 调用 `contentResolver.takePersistableUriPermission(uri, FLAG_GRANT_READ_URI_PERMISSION)`
4. **先扫描成功**，再把 `treeUri` 写入 DataStore、替换播放队列，最后再释放旧目录的 persistable 权限
5. 用 `DocumentFile.fromTreeUri()` 列出直接子文件（v1 不递归子文件夹）

默认 **只扫所选目录这一层**。

### 8.2 文件过滤

**只按扩展名入列：** 文件名以 `.mp3` 或 `.wav` 结尾（忽略大小写）。

- MIME 不作为准入条件。名为 `song.bin`、MIME 为 `audio/mpeg` 的文件**不进入**列表
- 隐藏文件（以 `.` 开头）忽略
- 0 字节但扩展名合法的文件可以进入列表；播放失败按第 16 节处理

### 8.3 排序

使用 `Collator.getInstance()`（当前系统 locale），`strength` 设为 `Collator.PRIMARY`。**不要**再套 `String.CASE_INSENSITIVE_ORDER`。

比较器：先按 `displayName` 用 Collator；相等则按 `documentUri.toString()` 比较，保证次序稳定。

v1 **不做**自然数字排序。`file2` 可以排在 `file10` 后面，这是 Collator 的正常结果。

### 8.4 目录名展示

优先 `DocumentFile.fromTreeUri(treeUri).name`。取不到时展示「已选择的目录」，不展示一长串 `content://`。

### 8.5 曲库状态（空目录 ≠ 权限失效）

| 情况 | `LibraryState` | 列表文案 |
|---|---|---|
| 从未选过目录，或 DataStore 无 `tree_uri` | `NoDirectory` | 「请选择包含音频的文件夹」；按钮为「选择目录」 |
| 正在扫描 | `Loading` | 可短暂占位，不弹系统选择器 |
| 目录可访问，有或没有音频 | `Loaded` | 无文件时：「该目录没有 mp3 或 wav 文件」。保留授权，用户可稍后往该目录加文件后再用「更换目录」重新选一次同一目录；v1 不提供刷新按钮，回到前台也不自动重扫 |
| persistable 权限失效或目录不存在 | `PermissionLost` | 「无法访问上次的目录，请重新选择」；按钮为「选择目录」 |
| 扫描过程出错 | `Error` | 显示错误信息 |

权限失效时：不崩溃、不自动弹系统目录选择器。

### 8.6 更换目录

顺序必须是：

1. 对新 `treeUri` `takePersistableUriPermission`
2. 扫描新目录（IO 线程）
3. 扫描成功后：写入 `tree_uri`、用新列表替换 ExoPlayer 队列（第一首、进度 0、暂停）、更新 UI
4. **然后**再释放旧目录的 persistable 读权限

若第 1 或第 2 步失败：保留旧目录授权、旧列表和当前播放队列，只提示无法读取新目录。

### 8.7 列表何时更新

v1 不提供刷新按钮，Activity 回到前台时也不自动重扫。用户在已授权目录中新增文件后，列表要到下次「更换目录」（可再选同一目录）或进程被杀后冷启动扫描时才会更新。

## 9. 播放引擎与后台

### 9.1 组件

- 在 `PlaybackService.onCreate()` 里创建一个 `ExoPlayer`，随 Service 释放。不要再做全局 Singleton
- `MediaSession` 对接系统通知、蓝牙/耳机按键（播放/暂停/上一首/下一首与 App 内按钮同一套命令）
- `MediaSession.Builder.setSessionActivity` 指向 `MainActivity`（`singleTop`）。点媒体通知空白处必须打开本 App，不能落到系统默认音乐 App
- Service 类型：`foregroundServiceType="mediaPlayback"`
- 媒体通知由 `MediaSessionService` + `DefaultMediaNotificationProvider` 管理，v1 不手写通知渠道。小图标为 `ic_stat_player`（白色音符）。无内嵌封面时，`MediaMetadata.artworkData` 使用桌面应用图标，避免系统默认播放三角
- 暂停或失败一段时间后，Media3 可能自动退出前台状态，进程可被系统回收；下次冷启动再从 DataStore 恢复进度

ExoPlayer 创建时显式配置：

- `setAudioAttributes(usage = USAGE_MEDIA, contentType = MUSIC, handleAudioFocus = true)`
- `setHandleAudioBecomingNoisy(true)`（拔耳机暂停）
- `setSeekBackIncrementMs(3_000)`（配合上一首「超过 3 秒回开头」）
- `repeatMode = REPEAT_MODE_OFF`，不开启 shuffle

### 9.2 播放列表如何交给播放器

ViewModel 仅在「需要换队列」时把 `List<AudioFile>` 转成 `MediaItem` 交给控制器（选目录成功、冷启动恢复）。**重新进入已有队列的 Service 时不要 `setMediaItems`。**

- `MediaItem.Builder().setUri(documentUri).setMediaId(uriString).setMediaMetadata(title = displayName, artwork = 应用图标)`
- 设置列表后必须调用 `prepare()`，再按需 `pause()` 或 `play()`
- 当前曲播完：ExoPlayer 默认播下一首；最后一首结束时 `STATE_ENDED`，UI 显示暂停、进度停在结尾

### 9.3 点击列表

- 队列已 `prepare()` 的前提下：`seekTo(index, 0)` 然后 `play()`
- 从该文件开头播放，不是恢复该文件上次进度（「上次进度」只用于冷启动恢复，不用于点击另一首歌）

### 9.4 上一首 / 下一首

- 下一首：当前不是最后一首则切到下一首并从 0 播放（`seekToNextMediaItem()` + `play()`）；已是最后一首则忽略，不循环到第一首
- 上一首：**当前曲已播放超过 3 秒时，先回到本曲开头；再按一次才到上一首。** 已是第一首且未超过 3 秒则忽略。用 ExoPlayer 的 `seekToPrevious()` + `seekBackIncrementMs = 3000` 实现
- 进度条拖到任意位置只改变当前曲位置，不切歌

### 9.5 进度条

- UI 约每 200–500ms 读 `player.currentPosition`
- 用户拖动时暂停进度上报，松手后 `seekTo(position)`；Service 在 seek 完成后**立即**写 `position_ms`
- duration 未知（0 或 `C.TIME_UNSET`）时进度条不可拖、显示 `--:--`

### 9.6 后台续播

用户按 Home：Activity 不可见或被销毁，`PlaybackService` 保持前台，ExoPlayer 继续播。

Android 8+ 后台播音频必须有可见媒体通知。通知由 Media3 根据 `MediaSession` 提供：当前文件名、播放/暂停、上一首、下一首。不做音量条。点通知（非按钮）打开 `MainActivity`。

v1 **不申请** `POST_NOTIFICATIONS`。与 `MediaSession` 关联的媒体通知属于 Android 13 该权限的豁免项；启动前台媒体服务也不依赖用户授予该运行时权限。界面不要提示「拒绝通知后无法后台播放」。Manifest 中也不声明该权限。

## 10. 状态持久化

### 10.1 存储内容（DataStore）

| 键 | 写入方 | 含义 |
|---|---|---|
| `tree_uri` | ViewModel | 已授权目录 |
| `file_uri` | Service | 当前/上次播放文件 |
| `position_ms` | Service | 当前/上次进度 |

不存播放/暂停状态。冷启动（Service 新建）一律为暂停。Service 仍在播放时，不把「暂停」写回播放器。

ViewModel 和 Service **不得**同时写 `file_uri` / `position_ms`。

### 10.2 何时写入

| 时机 | 写入方 | 写入内容 |
|---|---|---|
| 选中新目录并扫描成功 | ViewModel | `tree_uri`；当前文件由随后的队列重置由 Service 写出 |
| 开始播某一首 / 切歌 | Service | `file_uri`，`position_ms = 0` |
| 播放中 | Service | `position_ms` 节流，约每 2 秒一次 |
| 用户 seek（含进度条松手） | Service | 立即写 `position_ms` |
| 暂停 | Service | 立即写当前进度 |
| 播放结束（`STATE_ENDED`） | Service | 立即写；最后一首则为该曲 duration |
| Service `onTaskRemoved` / `onDestroy` | Service | 立即写当前进度（尽力而为，见下） |

`onDestroy()` 在进程被系统直接杀死或用户强制停止时**不保证执行**。Activity 的 `onPause()` / `onStop()` 也不足以覆盖后台播放。因此：

- 正常暂停、切歌、seek、退出：立即保存
- 异常杀进程：最多可能损失最近一个节流周期（约 2 秒）的进度

自然播放结束停在最后一首结尾时，保存 `position_ms = duration`。冷启动后仍停在这首、进度条在结尾、不自动播。用户点播放则从该曲开头重播。

### 10.3 连接 Service 后的恢复顺序

连接 `MediaSession` 之后：

1. 若 Service 中**已有播放队列**（`mediaItemCount > 0`）：
   - 以 Service 为准。观察 `isPlaying`、当前 index、进度并展示。
   - **禁止** `setMediaItems`、**禁止**为了「符合冷启动不播放」而调用 `pause()`。
   - 曲库列表仍从已授权目录扫描，供 UI 展示；不要用扫描结果覆盖正在播的队列，除非 URI 集合与当前队列明显不一致且需要另案处理。v1：Service 有队列时只同步 UI，不重建队列。
2. 若 Service 是新建的、没有队列：读 DataStore
   - 无 `tree_uri` → `NoDirectory`
   - 有但权限失效 → `PermissionLost`
   - 有且可访问 → 扫描 → `Loaded`（可为空列表）→ 按 `file_uri` 匹配后 `setMediaItems` + `prepare()` + `seekTo` + **`pause()`**
   - 匹配不到（文件被删）→ 停在列表第一首、进度 0、暂停；列表为空则不设队列
3. 曲库扫描与播放恢复都在主线程外的 IO 完成后，再一次性更新 UI

## 11. 界面结构

单屏，竖屏优先。不强制横屏。

```
┌─────────────────────────────────┐
│  目录名              [更换目录]  │  ← NoDirectory / PermissionLost 时按钮为「选择目录」
├─────────────────────────────────┤
│                                 │
│  文件名 a.mp3                   │  ← 大字号，约 20sp
│  文件名 b.wav          (当前)   │  ← 当前曲高亮，不靠封面/图标
│  文件名 c.mp3                   │
│  ...                            │
│                                 │
├─────────────────────────────────┤
│  0:12 ────────●──────── 3:45    │  ← 进度条 + 已播/总时长
│                                 │
│       上一首   播放/暂停   下一首 │
└─────────────────────────────────┘
```

交互：

- 列表可滚动，底部控制区固定
- 当前播放项尽量滚进可视区（启动恢复和切歌时）
- `Loaded` 且 tracks 为空：「该目录没有 mp3 或 wav 文件」
- `NoDirectory`：「请选择包含音频的文件夹」
- `PermissionLost`：「无法访问上次的目录，请重新选择」
- 无独立设置页、无启动闪屏、无刷新按钮

颜色与字体：跟随系统浅色/深色。v1 不做自定义主题皮肤。

## 12. 权限清单

| 权限 | 用途 | 时机 |
|---|---|---|
| 无 `READ_EXTERNAL_STORAGE` | 用 SAF 授权的目录，不申请读全盘 | — |
| 无 `WRITE` | 只读播放 | — |
| 无运行时 `POST_NOTIFICATIONS` | 媒体会话通知为 Android 13 豁免项 | 不申请 |
| `FOREGROUND_SERVICE` | 后台播放服务 | 安装即可 |
| `FOREGROUND_SERVICE_MEDIA_PLAYBACK` | Android 14 前台服务类型 | 安装即可 |
| persistable URI permission | 记住用户选的目录 | 用户选目录之后 |

`AndroidManifest` 中 Service 声明 `foregroundServiceType="mediaPlayback"`。`MainActivity` 为 `launchMode="singleTop"`。v1 不声明 `VIEW` intent-filter，也不声明 `POST_NOTIFICATIONS`。

## 14. 播放状态机（v1）

```
未选目录 ──选择目录──► 已加载列表（暂停）
                              │
                    点击列表项 / 点播放
                              ▼
                         播放中
                          │  │
              点暂停 / 回桌面仍保持播放
                          │
                     暂停 ◄─┘
                          │
              最后一首结束 ──► 停止（STATE_ENDED，停在结尾）
                              │
                         再按播放 ──► 从该曲开头播放
```

回桌面 **不是** 状态变化：仍是「播放中」，只是 Activity 不可见。

Activity 被系统回收后重新进入：若 Service 仍在「播放中」或「暂停」，UI 必须回到对应状态，而不是走冷启动的「暂停恢复」。

## 15. 关键流程

### 15.1 首次使用

1. 打开 App → `NoDirectory` + 「选择目录」
2. 系统文件夹选择器
3. 持久化读权限 + 扫描 + 按第 8.3 节排序
4. 若有文件：当前曲为第一首、进度 0、暂停
5. 用户点击某项或点播放后才出声

### 15.2 再次打开

1. 连接 Service
2. Service 已有队列 → 只同步 UI，保持正在播放或暂停
3. Service 无队列 → DataStore → 扫目录 → 定位上次文件和进度 → `prepare()` + 暂停等待

### 15.3 更换目录

按第 8.6 节：新权限和新扫描都成功后，才替换队列并释放旧权限。新列表当前曲为第一首、进度 0、暂停（不自动播放）。

## 16. 异常与边界

| 情况 | 处理 |
|---|---|
| 文件在播放中被删除 | 当前项播放报错后，按 `mediaId`/URI 在**重扫后的列表**中定位下一首可播文件并播放；不要按报错前的 index 直接 `seekToNext` |
| 损坏/不支持的编码 | 提示「无法播放该文件」。将该 URI 记入本次失败集合，向后找下一首未失败项并 `prepare()` + `play()`；连续损坏则一直向后，直到成功或到达列表末尾后停止。`REPEAT_MODE_OFF`，不得绕回第一首形成重试循环 |
| 0 字节文件 | 扩展名合法则入列表；播放失败按上一条 |
| 同名文件 | URI 不同则都显示，文件名可以重复 |
| 目录内文件数千个 | v1 一次性列出（DocumentFile 在主线程外 IO）；若明显卡顿再改为分页，首版不做 |
| 耳机断开 | `setHandleAudioBecomingNoisy(true)`：暂停 |
| 来电 | `handleAudioFocus = true` 时系统会暂停或降低音量。产品要求挂断后**不自动恢复**。实现上拦截音频焦点恢复后的自动 `playWhenReady`；**须在真机上来电场景验证**，不能仅靠文档约定视为已保证 |
| 多窗口/旋转 | 配置变化由 Compose 保留 ViewModel，播放在 Service 中，不中断 |

## 17. 测试要点（实现后按此验收）

1. 选含 mp3、wav、其它扩展名（含 MIME 为音频但扩展名不是 mp3/wav）的文件夹：列表只有 `.mp3`/`.wav`，且按第 8.3 节排序

5. 播放中从最近任务重新进入（Service 未死）：仍在播放，进度连续，不被暂停
6. 杀进程后重开：目录、歌曲、进度恢复，处于暂停；进度误差不超过约 2 秒

12. 媒体通知封面为应用图标（或接近桌面图标），不是默认黑色播放三角
